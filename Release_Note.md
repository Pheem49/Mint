# Release Notes - Mint Agent v1.16.0

- Separated Live2D into the optional Mint Companion Tauri app in the same repository. Mint Desktop/Web no longer load or bundle Shiroko/Cubism or wait for model readiness; proactive suggestions, the existing widget, and Project Avatar remain in Mint. Companion provides a floating character, manual/automatic expressions, accessories, interaction areas, local instance/session selection, and plain chat using Mint's existing memory and queue. Added an authenticated loopback protocol with session/turn snapshots, shared orchestration status, request deduplication, reconnect without message replay, independent preferences, and separate Linux/Windows/macOS packaging workflows. Added transport, state, endpoint, and npm packaging tests and operating documentation. CLI/Desktop launcher caches track the shared protocol crate; the npm CLI package retains the complete Rust workspace without shipping the Live2D assets.

- Added a shared Notifications settings tab for Desktop and Web with a master switch, reply/approval/system categories, OS and in-app delivery controls, permission status, and test delivery. Saved preferences now filter notifications and preserve existing behavior for older configs.

- Connected Desktop system/background notifications to a themed in-app notice; notification clicks open their originating conversation, Web clears all outstanding notifications, and delivery failures appear without interrupting chat completion. Desktop delivery now uses an awaitable native command with OS action handling.

- Fixed an MCP lock-order deadlock between notification draining, raw resource/prompt requests, and checked stdio tool dispatch. Notification draining now releases the session registry before waiting for a session, so a blocked server cannot prevent unrelated tool calls. Added a regression test that verifies concurrent notification draining and tool execution, with bounded waits and worker cleanup on failure.

- Fixed the five MCP/Device review findings: cancellation during discovery/approval now interrupts the run and propagates to subagents without contaminating later turns; paginated catalogs, validated commands, and Device polls stay bound to one live session with no mid-invocation reconnect; native tool feedback and repeated-failure tracking use typed status for denied/intercepted approvals and successful diagnostic text; Full-Screen TUI and shared slash commands expose validated 1–3600-second timeouts; and `mint_core::mcp_result` follows the core's flat module exports. Session loss after Device dispatch retains the receipt and reports unconfirmed completion. Added regression coverage and updated connector guidance.

- Added schema-validated MCP commands across raw CLI/API and agent calls, with paginated, bounded session catalogs, local JSON Schema validation, blocked external schema references, and refresh on configuration changes, reconnects, list-change notifications, or a 60-second TTL. Agent preparation reads full tool definitions before executing a new proposal and retains them across context compaction without treating discovery as execution or granting command access. Native Ollama now receives the system instructions used for this review.
- Added opt-in Mint Device v1 verification and a dependency-free Node stdio mock motor/camera connector. Commands expose typed receipts and observations; agent chat checks device/operation/target identity and fresh observation sequences under one command-and-verification deadline. Permissions and schemas for status reads are checked before dispatch. Full-Screen TUI, Classic CLI, and Desktop/Web distinguish accepted, running, verified, failed, and unconfirmed device states and show target/actual readings. Saved observations and MCP attachments survive TUI history reload/external sync and shared-renderer history reload. Cancellation stops polling without issuing a physical stop. Added protocol, schema, model-request, verification, cancellation, and UI coverage; real USB/Serial/MQTT adapters remain device-specific.

- Added typed MCP results with explicit success, failure, timeout, and cancellation status. Agent calls normalize text, multiple images, embedded text/binary files, resource links, and structured content while preserving the raw MCP JSON API. Desktop/Web render previews, full-size images, downloads, links, and warnings independently of the assistant's summary; CLI prints artifact locations. UUID references retain attachments across history reloads without persisting base64 in activity. Validated images have 20 MiB/item and 50 MiB/result decoded limits; a setting disables model image input while preserving attachments for text-only models.
- Fixed one-call MCP approvals to grant access only to that invocation. Approval feedback and hook-blocked calls report failure without claiming that the tool executed; legacy blocked results display the same failed status.
- Added per-server MCP tool deadlines (`timeoutSecs`, default 300 seconds, range 1–3600), editable in MCP settings or `mint mcp edit --timeout-secs`. Stdio, SSE, and JSON HTTP waits are cancellable, with optional bounded progress, elapsed time, and exact-request cancellation notifications. Chat cancellation includes subagents and preserves shared sessions; dropped waits clean up pending requests. Timed-out/canceled calls report unconfirmed remote completion and do not retry automatically. Server initialization no longer blocks unrelated servers. Activity invocation IDs remain unique when provider tool IDs repeat, and completion cleanup cannot unregister a newer run in the same chat. Active MCP jobs are not resumed across restarts. Added mock transport, result persistence, history, and shared-renderer regression coverage; no real Blender integration was required.

- Highlighted sent user messages in the Full-Screen TUI with a full-width gray background and an inline `You ›` label. Message text begins immediately after the label and wraps when it exceeds the available width; explicit newlines are preserved. Long and multiline messages retain the background across wrapped rows and padding, with readable foreground colors in Auto/Dark and a light gray background in Light theme. Text styles and logical keyboard-copy selection are preserved, with copied first lines matching the inline label. Assistant replies keep their existing presentation. Desktop/Web already distinguish user messages with rounded bubbles. Added terminal-rendering coverage for short inline messages and narrow/wide wrapping, including Thai text, theme contrast, and keyboard copy.

- Fixed Live conversation appearing inline below the chat composer on Web. The call now renders through a body portal as a centered viewport popup with a dim backdrop, scroll containment and restored page scrolling/focus on end. Shared call styles own their layout and controls without depending on the Model pane stylesheet; removed duplicated legacy Live CSS in Desktop/Web. Added browser coverage without Model CSS and inside a transformed, clipped chat host.

- Redesigned the full-application ChunkErrorBoundary fallback with the supplied VoicePoweredOrb shader, responsive centered recovery copy and shared shadcn buttons. Orb voice control is disabled so visiting an error page never requests microphone access. Preserved Back to Chat, refresh/cache recovery, and Desktop window controls. Fallback colors are independent of app theme loading; WebGL fallback and reduced motion reuse the orb implementation. Added browser checks for the real failed-route boundary, shader rendering, no microphone access, responsive recovery controls, route reset and animation cleanup.

- Removed the composer voice aura animations and old Ready/listening bar with its pulsing dot. VoicePill now supplies recording feedback through its authored monochrome capsule, elapsed clock, waveform and cancel gesture. Transcription/permission feedback remains as plain text below the composer. Removed send/stop-button glow and the light-theme composer shadow in Desktop/Web; call UI remains separate.

- Removed legacy microphone button selectors and recording/light-theme/mobile appearance rules from Desktop/Web chat styles, plus the unused red pulse animation. The composer now identifies its VoicePill as voice-input-btn with component-owned styling and explicit responsive grid placement, without relying on the old mic-btn ID.

- Replaced the Gemini Live conversation's CSS pulse with the supplied OGL VoicePoweredOrb shader, driven by the existing call microphone and streamed reply analyser without a second microphone request. Added a responsive orb-centered call layout, connection/error status, retained transcripts and voice switching, labelled pause/resume and end-call controls, focus containment/return, reduced motion and a graphics fallback. Added shared shadcn-compatible components/ui, Button and cn, aliases and Tailwind utilities for Desktop/Web without Preflight. Fixed Live startup cancellation so late permission/session results are released, stopped queued playback on end, closed audio contexts, and ignored stale session events. Added UI and browser lifecycle/shader checks plus a standalone source demo and setup documentation.

- Replaced the shared Web/Desktop chat microphone button with the supplied React Bits VoicePill: 28px pill, 200ms opening, elapsed clock, simulated scrolling waveform, tap-to-toggle, hold-to-record after 300ms, and a 64px left-slide cancel gesture. The capsule follows the actual recorder state and reserves composer space while open. Normal stop retains native transcription/send and Web dictation into the composer. Escape, slide/pointer cancellation, blur, disable, and unmount discard the recording; added a native discard command that bypasses provider transcription and Web SpeechRecognition abort cleanup. Serialized native startup/stop/cancel requests to prevent held-release races and suppress canceled late transcripts. Added accessible state/focus, reduced-motion styles, lifecycle regression tests, and browser interaction checks. Gemini Live remains a separate call control.

- Replaced 27 native Web/Desktop dropdowns with the supplied React Bits GlideSelect design across Settings, Image/Video Studio, scheduled tasks, MCP authentication, Code hub sorting, review history, rewind checkpoints, and Live Translate. Retained dynamic options, custom-model entries, numeric checkpoint values, disabled states, and existing value/save callbacks. Added the Hugeicons dependencies, 180ms menu pop, 220ms gliding highlight, tags, and remembered hover position. Menus render through a portal to avoid clipped scroll containers, fit the viewport, scroll long lists, support keyboard/typeahead and touch scrolling, and expose visible focus and reduced-motion behavior. Added field regression tests and browser interaction checks. Searchable chat-model, workspace, and branch menus retain their existing interfaces.

- Fixed different workspace lists between chat and Code hub. The dashboard now builds one ordered catalog from recent folders, the active workspace, and session workspaces, normalizes/deduplicates paths, and supplies it to both pickers. Windows drive roots retain their absolute trailing separator. Code hub no longer adds or sorts session folders independently. Folders opened from Code hub enter the shared recent list without changing the active conversation's workspace.

- Unified the Code hub Project picker and chat Workspace picker through the same searchable WorkspaceSelector and shared styles on Desktop/Web. Both show folder names, full paths, and the current selection, with Open folder and keyboard dismissal. Code hub opens its menu below the toolbar and filters locally without reassigning the active conversation; folder cancellation preserves the current scope. Menu IDs are unique when multiple pickers are mounted. Web chat exposes the picker too, using the existing same-machine backend folder dialog.

- Added explicit context-compaction lifecycle events around native agent summarization. TUI/classic CLI and Desktop/Web show an animated gradient `Compacting context` label with a compaction-only timer and English explanation (`Summarizing earlier steps to continue working`), then return to working status. Success and actionable failure notes remain in the activity history; failed summarization retains the original context. Short histories do not announce compaction, and post-compaction context percentages wait for fresh provider usage. GUI animation honors reduced-motion and forced-color settings. Subagent compactions track pending lifecycles, including concurrent invocations with the same name; the collective indicator stays active until every summarization finishes.

- Consolidated Desktop workflows around `npm start`, `npm run dev`, `npm run build:desktop`, and `npm run package`. Start fingerprints Rust, UI, configuration, dependency locks, and build environment; it reuses successful unchanged builds and stops on failures or edits during compilation. Full builds/packages record successful receipts without opening the app. Previous names remain compatibility aliases, while Tauri uses explicitly named UI-only steps. Linux packaging retains the portable tarball and renamed deb installer. Builds with forwarded custom configuration/features cannot validate the default startup cache.

- Source-checkout `mint` launches now fingerprint CLI/Core sources, Cargo inputs, and embedded catalogs/release notes. Changed or unverified builds compile the release CLI before launch; unchanged builds open immediately. Build failures and source changes during compilation stop without launching an older binary. Arguments and the invoking directory are preserved for CLI, web, and auto commands; explicit MINT_BIN overrides and packaged installs retain their existing behavior.

- Changed agent skill discovery to a name/description/path catalog for workspace, global, and taught skills. Relevant skills load through capability-checked full-file reads; explicit skill selection and memory recall no longer preload bodies or claim a load. Successful reads persist exact content per canonical path and chat, reset on chat clear/delete, and require another read when the file changes. Only unchanged, fully retained content receives READ status, and that content is attached to every native/JSON request across history rebuilds and compaction. Project rule files remain mandatory context. CLI and Web/Desktop activities now show Reading skill, Loaded skill, failures, and partial previews separately, with matching parallel completions. Full successful skill reads bypass ordinary output truncation; unchanged exact bodies already present in the request count as READ even when they exceed the cached replay budget.

- Added a Project selector to the shared Web/Desktop Code hub, populated from session workspaces, recent folders, and the active workspace. Selecting a project filters the hub directly without reassigning the active chat. Empty projects now show the actual number of CLI sessions outside that project and a Show all sessions button; search misses keep their separate empty state.

- Changed the Full-Screen TUI watermark to continue rotating in the same direction after the one-second leaf-face pause, completing a full revolution back to M. Both 3-second eased half-turns and click-to-animate behavior are retained. Updated the animation regression test to reject reverse rotation.
- Slowed the Full-Screen TUI watermark to 3 seconds per half-turn with cosine easing and 200 angular frames for finer movement (up from 100). It holds the leaf face for one second between half-turns, for a seven-second cycle, preserving click-to-animate behavior and deadline-based polling. Updated timing and easing regression coverage.
- Added the npm `mint-web` launcher as a shortcut for `mint web`, reusing the existing native binary lookup and preserving options and exit codes. Added launcher integration tests and documented the shortcut. Cargo-only installs continue to expose `mint web`.
- Replaced the CLI Thinking moon-phase marker with the same single-column `✦` star used by Web/Desktop. The Full-Screen TUI's existing text glow now includes the star; elapsed time, randomized thinking verbs, and tool progress indicators are preserved. Classic CLI uses the same marker.
- Updated the Web/Desktop waiting indicator to `✦ Thinking · 5s · Esc to cancel`: the decorative star shares the text glow, while elapsed time and the cancellation hint remain static. Active agent/model labels are retained with the same separators.
- Replaced the Web/Desktop waiting-for-response spinner with a left-to-right text glow inspired by the Full-Screen TUI Thinking indicator. Theme text colors drive the effect; elapsed time and cancellation hints remain static. Reduced-motion and forced-colors preferences receive plain readable text. Streaming behavior and TUI remain unchanged.
- Fixed Web/Desktop opaque theme rendering for saved settings containing `surfaceStyle: glass` alongside `glassBlur: none`. The runtime now matches Settings and disables translucent surfaces when Glassmorphism is off, including the model selector. Added regression coverage for disabled and enabled glass modes.
- Updated the shared Web/Desktop model selector to follow the selected theme: popover/pane surfaces, borders, hover states, effort and capability badges, selected-model/effort highlights, scrollbars, and Thinking switch colors now use semantic theme tokens. Replaced the undefined surface token, respected the configured glass blur, and added themed keyboard focus outlines. Provider logos retain their brand colors.
- Changed Personal Memory's Web/Desktop reading view to a single bordered, scrollable text frame, preserving the original text and line breaks instead of splitting preferences into bullet points. Kept the larger readable typography and existing Edit instructions flow.
- Moved Memory & Profile from Workspace to Account in Web/Desktop Settings and renamed it Personal Memory. It appears alongside Profile; the existing memory editor and saved data are preserved.
- Redesigned Web/Desktop Memory & Profile around reading: shared-memory scope is explained up front, nickname has a labeled full-width field, and preferences display as spaced readable items with an Edit instructions / Reading view switch. Editing uses a larger proportional-font textarea, retains the exact stored text, and keeps the existing Save Settings flow. Added empty-state guidance and a distinction between profile/preferences, saved facts, project memory, and conversation history. Layout adapts to narrow screens and retains theme tokens.
- Fixed Web/Desktop Code hub Current Project filtering: the count now reflects the visible CLI sessions, the selected project is named with its full path in a tooltip, and empty states distinguish an unselected workspace from a project without CLI sessions. Workspace matching normalizes separators, surrounding whitespace, and trailing slashes while excluding unassigned sessions and other directories. Project conversations remain excluded; CLI session storage and resume behavior are unchanged.
- Added HTML/HTM workspace context-menu actions: Open in Browser uses the external browser; Preview in Mint reuses the existing Mint Co-browsing browser window. A dependency-free loopback static server serves workspace assets, reuses one live server per workspace/owner, and appears in Background Terminals with Stop and shutdown cleanup. Hidden paths and symlink escapes are denied. Local Web and native Desktop verify the HTML response before opening. Remote Web clients receive a same-machine requirement. CLI/TUI `/preview <relative HTML path>` provides the same server and URL.
- Review now displays AI edits and Git changes relative to the selected workspace root in the file tree, file bar, filtering, and history matching. Absolute paths outside that root and relative paths escaping it are excluded; path prefixes respect directory boundaries and Windows separators.
- Moved workspace Undo and file history into the shared Web/Desktop Review panel. Added Changes and File history tabs, selected-file Undo controls, action details, and an explicit confirmation showing the file and restore operation. Undo retains reverse-order history and conflict checks; stale confirmations cannot undo a different action. CLI `/history` and `/undo` remain available.
- Added background terminal management across Full-Screen TUI, Classic CLI, Web, and Desktop. A workspace-scoped counter sits beside Agent/Plan mode in the GUI and opens a nonmodal job/output panel with All workspaces, Follow, and Stop controls. `/shells [all|show <id>|stop <id>|kill <id>]` is available on all surfaces.
- Background jobs carry backend-scoped IDs, workspace/chat/owner metadata, timestamps, confirmed stopping states, and bounded output. Authenticated API and native Desktop controls enforce ownership and workspace capabilities; output viewing never consumes the AI's read cursor. Retain up to 100 finished records per backend, with active jobs preserved. Status polling reports unavailable connections without inventing a zero count.
- Timeout-promoted commands now expose live bounded output. Development-server guidance requests background execution immediately; Open browser appears only after a loopback HTTP response and listening-process ownership check. Remote Web clients see backend-local addresses without opening their own localhost. Normal backend shutdown terminates tracked process groups; chat changes and AI cancellation preserve background jobs. Separate backends remain independent, and jobs are not persisted across restarts. Foreground captured output now uses the same 256 KiB per-stream limit.
- Fixed project conversation assignment: New chat in project persists its workspace immediately, and ordinary New chat inherits the currently selected workspace. Explicit project drafts survive session-list cleanup. Workspace selections and `/workspace` changes persist to the active conversation; sidebar refresh compares workspace metadata and ignores stale list responses. Opening an unassigned existing conversation in a selected Workspace binds only that conversation to the selected project. Agent and plain-chat paths save workspace metadata before invoking a provider, including failed requests. Added the missing Web session-workspace endpoint and surfaced assignment errors in both renderer adapters.
- Fixed Desktop/Web error notifications covering chat controls. Errors now occupy their own bounded layout space below the titlebar, with scrollable details and an accessible close button. HTTP 429 errors show a short rate-limit explanation; the composer and model picker remain accessible while the notice is visible. CLI error rendering is unchanged because it has no floating notification overlay.
- Added shared repeated-failure detection for CLI, Desktop, and Web in native and JSON tool modes. Identical tool/arguments/error failures warn after three model rounds and stop after five; batch duplicates count once per round. Changing the arguments or error starts a new streak, and a successful invocation of the same tool clears its streak. Retry counters and Mint tips are excluded from comparison, and successes in unrelated tools do not erase a stuck tool. The 40-step overall limit remains.
- Updated the npm package, Rust workspace (Core/CLI/Desktop), Tauri app metadata, lockfiles, and release tag examples to version 1.16.0.

- Workspace right-click now opens a menu. Moving a file or folder to Trash requires an explicit menu selection and waits for confirmation; Cancel leaves the item untouched. Workspace removal now uses the system Trash instead of permanent deletion and reports failures without falling back to deletion.
- Added persistent workspace file history with Undo for creation, Rename, Move, Move to Trash, and native AI file edits. Workspace menus show the exact action to undo, and Ctrl+Z uses text undo in editable fields and file undo in the workspace. Restore refuses changed files and occupied destinations. AI `write_file` and `apply_patch` actions save pre-edit copies even without Git. `/history` and `/undo` work in Desktop, Web and the CLI TUI; `mint history [--undo]` exposes the same history in the CLI.
- Fixed AI `apply_patch` calls whose patch object was JSON-encoded as a string. Native tools and JSON decisions decode the patch while requiring an explicit, consistent target and preserving strict argument types and approval. Tool guidance includes the correct object example. Argument errors omit oversized patch bodies, and Desktop/Web errors show a compact message with expandable, scrollable details. Argument correction is tracked per tool, with five correction retries renewed after that tool executes successfully. Failed or blocked execution does not reset the counter, and changing arguments alone does not reset it. The shared agent keeps its 40-step run limit across CLI, Desktop, and Web.
- Live Translate now uses the provider and model selected in Mint's chat model picker for each translation request, including custom and local providers, instead of always using Gemini.
- A model that cannot accept images reports its own error; Live Translate does not switch providers automatically.
- Reduced the in-frame translation text to a compact 14px style close to the source text shown in the selected area. The translation surface is translucent and blurs the captured source beneath it while keeping clicks available to the game or reading window.
- Removed the unused pre-Live-Translate screenshot helper, silent-capture API, vision-ready event plumbing, and Web-only screen-picker adapter. Manual chat screen capture continues through its separate capture flow.
